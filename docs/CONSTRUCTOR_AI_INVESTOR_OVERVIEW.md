## The proposition

**CONSTRUCTOR AI** is an inspectable software creation platform under development. Its intended differentiation is a governed engineering workflow: explicit requirements, permission-controlled model use, isolated execution, reproducible tests and reviewable evidence before release.

**Today:** a potential customer can explore the [public Template Studio demo](https://oromaskevic23-cmd.github.io/Capital-Core-Public/reference/constructor-ai/studio/studio.html), inspect [source code](https://github.com/oromaskevic23-cmd/CONSTRUCTOR-AI), and reproduce the local exports. This is a **proof of a narrow product workflow**, not proof of generalized AI software engineering.

## A concrete starting use case

The first proposed evaluation is a small, local, single-user application:

| Candidate | Demo capability | Not included in the current prototype |
| --- | --- | --- |
| Task Manager | Local task entry and management, reviewed template export | Enterprise identity, shared workspaces and hosted delivery |
| Business CRM | Local customer pipeline reference, editable source | Live sales-platform integrations, production database and payments |
| Business Dashboard | Local business dashboard reference | Enterprise analytics feeds or managed cloud hosting |

All current exports use reviewed templates, local browser storage, automated integrity checks and JSON backup/restore. The [commercial release gates](https://github.com/oromaskevic23-cmd/CONSTRUCTOR-AI/blob/main/docs/COMMERCIAL_READINESS.md) describe the work still needed before paid production use.

## What is not yet verified

The current Template Studio **does not** produce arbitrary production applications from open-ended prompts. A complete real-model app workflow, independent human security review, production multi-user hosting, signed customer acceptance, paying customer revenue, contracted investment and validated acquisition value are **not established by this public evidence**.

The planned next gate combines VELION with isolated execution, independent QA and Approval Gateway under HANTER. Federated orchestrators, Nano Core Agents, AI Passport, Enterprise Skills, Guardian Core, Audit Ledger, Zero Trust and the Public/Private Boundary are architecture requirements; their documentation does not prove a production service.

## Proposed pilot, with explicit acceptance

1. A prospective partner identifies a **single narrow task** and non-sensitive sample data. No credentials or customer private records in public issues.
2. Both sides agree in writing on scope, evaluation environment, required checks, intellectual-property/licensing boundaries and success/failure criteria.
3. The technical team reproduces a fixed revision and documents independent observations, including any defects.
4. Only after successful gates can the parties discuss a broader deployment, integration, paid contract or investment.

**Pilot evidence is pending.** No pilot customer has been identified as signed through these public documents. Any financial or ownership terms require a separate agreement and review.
