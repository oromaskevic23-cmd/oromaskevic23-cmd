## Critical negative result — not hidden

The private IMPERIAL ONE integration branch has a **known P0 release blocker**: when a privileged same-host attacker restores the tenant database together with its authority sidecar from an earlier snapshot, work can resume even after a local Owner STOP. Developer tests have reproduced this **security failure** and the local release checker classifies it as **BLOCKED**. A signature, a same-host gateway and ordinary passing functional tests do **not** prove independent stop authority. This project is **not** cleared for real payments, production deployment or customer invoices.

**Disclosure boundary:** the private source and test fixtures are not publicly accessible. Public evidence describes the scope; outsiders must not treat a claimed local test log as independent replication. An independent reviewer needs a controlled access arrangement and pinned source commit.

## Exact distinction between evidence classes

| Evidence | What it proves | What it does **not** prove |
| --- | --- | --- |
| Source code, API schema and architecture | Design can be inspected and reviewed | That the program runs or delivers customer value |
| CI or local developer PASS | A named command completed in a specific environment, if logs and SHA are retained | Independent QA, production readiness, future pass or real-model reliability |
| Synthetic end-to-end / screenshot replay | A bounded reference scenario | Working browser-to-server interaction with live customer inputs |
| Real-model held-out evaluation | Accuracy/safety on a declared dataset and pinned model | Open-domain parity, universal intelligence or commercial traction |
| Independent review | Third-party findings for a scoped revision, with provenance | General certification of every future revision |
| Pilot metrics from consenting users | Real context-dependent utility and costs | Causal ROI without sound baseline and study design |
| Paying customer receipts | Economic validation at a specific scale | Enterprise maturity or guaranteed future adoption |

Current status: **no independent product acceptance or paying pilot is claimed on this page.**

## Five gaps and the evidence needed to close them

1. **Focus:** Lead with one real agent demonstration, not 30+ repositories. The primary public paths are CONSTRUCTOR AI, VELION and CYBER HAK; the immediate competition engineering focus is IMPERIAL ONE. Architectural domain repositories remain discoverable but are not marketed as additional launched products.
2. **External validation:** Publish a bounded reproduction package, a real-model scorecard and a transparent negative-test matrix; invite a technically independent reviewer under appropriate access controls. Track reviewer identity, pinned SHA, methods, findings and unresolved issues.
3. **Maturity language:** Four new security-domain repositories already state `LOCAL TESTED REFERENCE / INDEPENDENT QA PENDING` in their main READMEs. Treat all as local references until signed external acceptance; no `enterprise-grade` label by itself grants maturity.
4. **Crypto isolation:** The separate [CRYPTO IMPERIAL Ecosystem Boundary](CRYPTO_IMPERIAL_ECOSYSTEM_BOUNDARY.md) contains tokens and related artwork without placing token-market or wallet claims beside AI software acceptance. Moving the showcase in the README does not move or modify contracts and does not create liquidity, cash or regulatory status.
5. **Licensing clarity:** Public GitHub visibility is not equivalent to an OSI-approved open-source license. Each repository's actual license governs use; choosing MIT/Apache-2.0 for a separate module, or a formal source-available/commercial grant for protected core code, requires explicit Owner/legal authorization. No silent relicensing is allowed.

## A real external reviewer challenge (reproducible and falsifiable)

Before awarding trust, ask the founder or project engineer to provide:

- A fresh clone or permitted archive of an exact revision and a clean-environment single-command demo.
- One original task that was NOT one of the prepared three templates, with source files and a reproducible build.
- A real, identified local model and a held-out dataset with raw predictions, false positives, refusals and latency/cost.
- A live, continuous runtime capture, not edited screenshots, plus original logs.
- A negative-test report demonstrating whether a supposedly stopped agent can resume after adversarial rollback.
- An independently operated review record and an actual user/pilot baseline; if unavailable, mark `NOT VERIFIED`, not `PASS`.
